🚀 Project Overview

The Battleship game is a classic naval combat game implemented as a modern web application using Vue.js. This single-page application provides an engaging single-player experience against an AI opponent, featuring traditional paper-and-pencil styling with responsive gameplay mechanics.

ℹ️ Version: MVP (Minimum Viable Product) - Fully functional core gameplay

Track shots, hits, accuracy, and game performance

🎮 How to Play

Battleship is a game of strategy and deduction where you try to sink all of your opponent's ships before they sink yours.

📋 Game Setup

  1. Choose Placement Method: Select "Auto Placement" for instant ship placement or "Manual Placement" to place ships yourself
  2. Place Your Ships: If using manual placement, click on your grid to position each ship. Ships can be placed horizontally or vertically
  3. Start the Game: Once all 5 ships are placed, click "Start Game" to begin

⚔️ Gameplay

  1. Your Turn: Click on any cell in the "Enemy Fleet" grid to fire a shot
  2. Shot Results:
    • × (Hit): You hit an enemy ship!
    • ○ (Miss): You fired at empty water
  3. AI Turn: After your shot, the AI will automatically fire at your fleet
  4. Continue: Alternate turns until one player sinks all opponent ships

🏆 Winning the Game

The game ends when all ships of one fleet have been sunk. The player who sinks all opponent ships first wins!

💡 Strategy Tips:
  • Try to hit different areas to locate ships
  • Once you hit a ship, target adjacent cells to sink it
  • Remember that ships can be placed horizontally or vertically
  • Pay attention to shot patterns to deduce ship positions

🚢 Ships & Equipment

The game features 5 different ships, each with unique size and characteristics:

Ship Name Size (Cells) Color Description
Carrier 5 Red Largest ship, takes 5 hits to sink
Battleship 4 Teal Large warship, takes 4 hits to sink
Cruiser 3 Blue Medium-sized ship, takes 3 hits to sink
Submarine 3 Green Medium-sized ship, takes 3 hits to sink
Destroyer 2 Yellow Smallest ship, takes 2 hits to sink

📐 Ship Placement Rules

  • Ships can be placed horizontally or vertically
  • Ships cannot overlap each other
  • Ships must be completely within the 10×10 grid
  • Ships cannot be placed diagonally
  • All 5 ships must be placed before starting the game
⚠️ Important: Once a ship is placed during manual placement, it cannot be moved unless you reset the entire placement.

🔧 Technical Details

🏗️ Architecture

The Battleship game follows a component-based architecture with clear separation of concerns:

Component Structure

  • App.vue: Root component managing game state and logic
  • GameBoard.vue: Reusable game grid component for both fleets
  • PlacementControls.vue: Ship placement interface and controls
  • Controls.vue: Gameplay controls and status display

Game Logic Modules

  • gameLogic.js: Core game rules, ship placement, shot processing
  • ai.js: AI opponent logic and shot generation
  • ships.js: Ship configurations and constants
  • utils.js: Helper functions and utilities

🔍 Detailed Bug Reports

Bug #1: Start Button Not Appearing

Issue: The "Start Game" button did not appear after completing ship placement in both auto and manual placement modes.

Root Cause: The PlacementControls component was tracking ship placement locally in its own state (placedShips array), while the actual placement logic was managed in the parent App.vue component. The component's local state was never synchronized with the actual board state.

Solution:

  • Made shipsPlacedCount a prop instead of local state
  • Updated allShipsPlaced to use the prop value from parent
  • Synchronized currentShipIndex between parent and child components
  • Added proper state management when switching between auto/manual placement

Files Modified: src/components/PlacementControls.vue, src/App.vue

Bug #2: Vue Template Error

Issue: Console error: [Vue warn]: Property "SHIP_CONFIGS" was accessed during render but is not defined on instance.

Root Cause: In App.vue line 15, the template used SHIP_CONFIGS.length directly, but SHIP_CONFIGS was only imported in the script section and not available in the template context.

Solution: Changed the template to use the totalShips computed property instead of SHIP_CONFIGS.length.

Files Modified: src/App.vue

Bug #3: Manual Placement Controls Error

Issue: Console error: Uncaught (in promise) TypeError: Cannot read properties of undefined (reading 'name') when all 5 ships were manually placed.

Root Cause: When currentShipIndex became 5 (after placing all 5 ships), the template tried to access SHIP_CONFIGS[5] which doesn't exist (array only has indices 0-4).

Solution:

  • Added condition to only show ship placement controls when currentShipIndex < totalShips
  • Added "placement complete" message when all ships are placed
  • Prevented accessing out-of-bounds array indices

Files Modified: src/components/PlacementControls.vue, src/App.vue

Bug #4: Column Label Alignment

Issue: The column labels (A-J) across the "Your Fleet" 10×10 grid were misaligned with the overall grid columns.

Root Cause: The column label cells had a height of 1.5rem while the grid cells had a height of 2.5rem, causing vertical misalignment.

Solution:

  • Changed column label cell height from 1.5rem to 2.5rem to match grid cells
  • Changed corner cell height from 1.5rem to 2.5rem for consistency
  • Added proper margin-bottom to column labels container

Files Modified: src/styles/main.css

Bug #5: Player Shots Not Appearing

Issue: After the first successful shot, subsequent shots did not appear visually on the "Enemy Fleet" board.

Root Cause: The game tracked missed shots for the AI's shots on the player's board (aiMissedShots) but did not track the player's missed shots on the enemy board. Additionally, playerMissedShots was created but never added to the Vue component's return statement.

Solution:

  • Added playerMissedShots state variable to track player's missed shots
  • Updated shot processing to add misses to playerMissedShots set
  • Passed playerMissedShots to the enemy GameBoard component
  • Added playerMissedShots to the return statement in setup function
  • Updated reset function to clear missed shots on new game

Files Modified: src/App.vue

Bug #6: Layout Shift After Manual Placement

Issue: When the last ship was manually placed, the ship placement controls moved from horizontal layout to vertical layout.

Root Cause: When the manual placement section was hidden and the "placement complete" message appeared, the flexbox layout caused the remaining content to reflow vertically.

Solution:

  • Added align-items: flex-start to .game-setup container
  • Removed the redundant "placement complete" message section
  • Ensured consistent layout behavior regardless of placement state

Files Modified: src/styles/main.css, src/components/PlacementControls.vue

🛠️ Environment Setup Issues

Node.js Installation

Issue: Node.js commands not found after installation.

Root Cause: VS Code was open during Node.js installation and didn't pick up the new PATH environment variable.

Solution: Restarted VS Code to refresh environment variables.

PowerShell Script Execution

Issue: npm commands blocked by PowerShell execution policy.

Root Cause: Default PowerShell policy blocks script execution for security.

Solution: Used Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass for the current session.

Git Configuration

Issue: Git commit failed due to missing user identity.

Root Cause: Git user.name and user.email were not configured.

Solution: Configured Git user identity with git config commands.

🧪 Testing Strategy

The debugging process involved systematic testing:

  1. Console Logging: Added extensive console.log statements to track state changes and function calls
  2. Component Props: Verified prop passing between parent and child components
  3. State Management: Checked reactive state updates and Vue reactivity
  4. Visual Testing: Manually tested each feature and user interaction
  5. Error Analysis: Analyzed Vue warnings and JavaScript errors in browser console

📝 Debugging Best Practices Applied

  • Incremental Testing: Tested each fix individually before moving to the next issue
  • Console Logging: Used strategic logging to identify where logic was failing
  • Vue DevTools: Leveraged Vue's reactivity system for state inspection
  • Component Isolation: Tested components in isolation when possible
  • Code Review: Reviewed template syntax and component communication patterns
✅ Debugging Outcome: All 6 bugs were successfully resolved through systematic debugging. The game now functions correctly with no console errors or warnings. The debugging process also improved the overall code quality and component architecture.
